[swclock] 2026-03-04 03:14:55  0ecc502  Alfredo Franco
  fix(pi-servo): add integrator anti-windup

  The integrator was accumulating unconditionally before the output clamp,
  causing classic anti-windup failure: when the phase error reached zero the
  inflated integral drove the output hard in the opposite direction, producing
  a continuously growing frequency correction oscillation.

  Fix details:
  - Compute the full PI output first, then decide whether to update the
    integrator.
  - Integrator is only updated when the output is NOT saturated, OR when the
    error is actively driving it away from the clamped limit (back-calculation
    anti-windup pattern).
  - Capture the pre-clamp PI value for accurate frequency-clamp event logging.

  - Passes macOS SDK sysroot to clang-tidy to resolve system header paths.
  - All checks are scoped to src/ only (excludes dep/iniparser and other
    third-party code).

[swclock] 2026-03-03 16:44:49  033bef5  Alfredo Franco
  perf: SwClock v2 improvements and performance documentation

  Five targeted improvements to the PI servo and clock discipline algorithm:

  1. Remove MIN_SLEW_PPM floor (was 100 ppm): the artificial floor caused a
     persistent +600 µs offset bias in steady-state tracking.

  2. Preserve integrator (pi_int_error_s) across ADJ_OFFSET calls: previously
     the integrator was reset on every offset adjustment, preventing steady-
     state error elimination.

  3. Fix gettime race condition: sample CLOCK_MONOTONIC_RAW before acquiring
     the rwlock to eliminate the time consumed waiting for the lock from the
     interpolated timestamp.

  4. Two-stage PI gains:
     - Pull-in mode  (|error| > 100 µs): Kp=200, Ki=8  — fast convergence.
     - Tracking mode (|error| ≤ 100 µs): Kp=20,  Ki=1  — low steady-state
       overshoot.

  5. Persist learned frequency offset to /tmp/swclock.freq_state across
     restarts, avoiding the initial frequency ramp-up on every invocation.

  Measured results (5-minute live PTP sessions, interface en5, 1000BASE-T):
    SwClock v2 vs v1:  offset bias -35%, RMS -31%, peak-to-peak -9%
    SwClock v2 vs sys: 100% sub-1ms samples (vs 57.9%), bias -79%, RMS -77%

  Adds docs/PERFORMANCE.md with full measurement methodology and result tables.
