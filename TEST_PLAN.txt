A. ANALYSIS OF EXISTING CHANGES

The following changes exist in the working tree (git diff HEAD + untracked files).
Each is classified as VERIFIED or UNVERIFIED.

------------------------------------------------------------
A1. src-app/macos/ptpd-app.c  (MODIFIED)
------------------------------------------------------------

  [VERIFIED] Signal handler re-registration after ptpd_init()
  ------------------------------------------------------------
  Problem:  ptpd_init() calls signal(SIGTERM, catchSignals) inside
            startup.c:982, overriding any handlers registered before it.
            Result: g_stop was never set; process ignored SIGTERM entirely.
  Evidence: Script sent SIGTERM→ process kept running; force-kill required.
  Fix:      Re-register signal_handler() immediately after ptpd_init().
  Test gap: No unit test verifies the re-registration order.

  [VERIFIED] CLOCK_REALTIME sleep replaced with CLOCK_MONOTONIC deadline loop
  ----------------------------------------------------------------------------
  Problem:  sleep(1) / nanosleep() internally blocks on CLOCK_REALTIME.
            ptpd applies a ~−26 s step correction on first lock, causing the
            1-second sleep to block for ~27 s thereafter.
  Evidence: CSV showed elapsed_s = −25.954 (negative); only ~12 rows written
            in a 600-second run.
  Fix:      50 ms nanosleep slices against a CLOCK_MONOTONIC deadline; wakes
            within 50 ms of SIGTERM regardless of CLOCK_REALTIME steps.
  Test gap: No automated test injects a clock step and verifies row count.

  [VERIFIED] Removal of ptpd_gettime() from monitor thread
  ---------------------------------------------------------
  Problem:  ptpd_gettime() → swclock_gettime() → pthread_rwlock_rdlock().
            swclock's background poll thread runs at 100 Hz and constantly
            acquires pthread_rwlock_wrlock().  macOS uses a writer-preference
            rwlock policy: once a writer is queued, new readers are starved.
            Result: monitor thread blocks permanently after ~30–34 rows.
  Evidence: Row count matched expected starvation onset; removing the call
            resolved it.
  Fix:      gettime_vs_system_ns column dropped from CSV entirely.
  Test gap: No concurrency test verifies the starvation scenario.
            No regression test guards against re-introducing a rdlock call
            in monitor_thread.

  [VERIFIED] Port 319 bind failure when previous ptpd-app leaks
  -------------------------------------------------------------
  Problem:  Leftover ptpd-app processes from earlier test sessions hold
            UDP port 319.  New instances fail netInit() → setupPIservo()
            never called → kP stays 0 → ptp_active=0 for entire 600 s run.
  Evidence: ptpd log: "failed to bind event socket" repeated across all runs
            of the comparison; 0 ptp_active rows in all three CSVs.
  Fix:      compare-servo-options.sh now runs sudo pkill -KILL -x ptpd-app
            before each run_config() invocation.
  Test gap: No test verifies the script cleanup step actually kills all
            instances before the next run starts.

  [UNVERIFIED] ptp_active = (kP > 0.0) heuristic
  ------------------------------------------------
  Assumption: setupPIservo() is called only after a successful netInit() +
              doInit() sequence, so kP > 0 reliably means ptpd is in
              LISTENING/SLAVE state with a functional network path.
  Risk:       In any configuration where ptpd acts as MASTER, kP is also
              set > 0 by setupPIservo().  The heuristic does not distinguish
              SLAVE from MASTER; it only distinguishes "servo configured" from
              "servo not yet configured" (failed netInit).
              Additionally, the monitor reads g_ptp->servo.kP without holding
              any lock.  If the protocol thread resets or reconfigures the servo
              concurrently, a torn read is possible.
  Test gap:   No test exercises MASTER mode, no test checks race on kP read.

  [UNVERIFIED] pthread_join(g_monitor_tid) always completes at shutdown
  ----------------------------------------------------------------------
  Assumption: After g_stop=1, the monitor's 50 ms slice loop breaks within
              50 ms, fclose(fp) completes, and the thread exits cleanly.
  Risk:       If the monitor were ever blocked on a slow swclock call (e.g.,
              a future re-introduction of a rdlock call) pthread_join would
              hang indefinitely, blocking the main process cleanup.
  Test gap:   No test injects a blocking condition and verifies join timeout.

  [UNVERIFIED] strip_arg() argv shifting correctness
  ---------------------------------------------------
  Assumption: Stripping two-argument flags (--servo-log path) correctly
              shifts the remaining argv elements and decrements argc.
  Risk:       Edge cases: flag at end of argv, flag value looks like another
              flag, duplicate flags, flags interleaved with ptpd's own flags.
  Test gap:   No unit test. Function is pure C and testable without ptpd.

  [UNVERIFIED] CSV column alignment — swclock else branch
  -------------------------------------------------------
  Code:  fprintf(fp, ",%lld,,,,,,", remaining_phase_ns);
  Claim: Produces exactly 7 swclock column values (remaining_phase_ns +
         6 empty metric columns), matching the 7-column header.
  Risk:  If the metric column count in the header ever changes (e.g., a new
         swclock metric is added), this hardcoded comma count will silently
         misalign all subsequent rows in the no-metrics case.
  Test gap: No test parses the CSV header and validates row column count.

B. PROPOSED TEST DIRECTORY STRUCTURE
================================================================================

Create src-gtests/ at the ptpd repository root (parallel to src/, src-app/).
Keep it separate from the swclock submodule's own src-gtests/ to avoid coupling.

  ptpd/
  ├── src-gtests/
  │   ├── CMakeLists.txt
  │   ├── test_helpers.h            # shared fixtures: mock PtpClock, temp files
  │   ├── test_strip_arg.cpp        # unit: argv stripping logic
  │   ├── test_monitor_csv.cpp      # unit: CSV column count validation
  │   ├── test_monotonic_sleep.cpp  # unit: CLOCK_MONOTONIC deadline loop logic
  │   ├── test_network.cpp          # integration: master reachability
  │   └── test_swclock_rwlock.cpp   # concurrency: rdlock starvation regression
  └── ...

The ptpd top-level CMakeLists.txt gains one option:

  option(BUILD_PTPD_TESTS "Build GoogleTest unit tests for ptpd-app" OFF)
  if(BUILD_PTPD_TESTS)
      add_subdirectory(src-gtests)
  endif()

C. INDIVIDUAL TEST FILE SPECIFICATIONS

------------------------------------------------------------
C1. test_strip_arg.cpp
------------------------------------------------------------
Purpose : Unit-test strip_arg() from ptpd-app.c without running ptpd.

Approach: strip_arg() is a file-static function. Two options:
  Option 1 (preferred): Extract strip_arg() into a separate translation unit
    src-app/macos/ptpd_app_args.c + ptpd_app_args.h, include in gtests.
  Option 2: Compile ptpd-app.c with a #define that suppresses main() and
    exposes strip_arg() via a header.

Test cases:
  T1: Strip --show-time (no-value flag) — argc decremented by 1, argv shifted.
  T2: Strip --servo-log /tmp/x.csv — argc decremented by 2, output buffer set.
  T3: Flag not present — argc unchanged, argv unchanged.
  T4: --servo-log at end of argv (missing value) — calls exit(1).
  T5: Two sequential custom flags — both stripped, ptpd args preserved.
  T6: Custom flag interleaved with ptpd flags — only custom flag stripped.
  T7: Duplicate --servo-log — first wins (current behaviour); document it.
  T8: Buffer overflow guard — value longer than PATH_MAX truncated.

Sanitizers: ASAN (buffer overflow T8), UBSAN (no UB in shifting).

C2. test_monitor_csv.cpp
------------------------------------------------------------
Purpose : Verify CSV column count is consistent between header and all row
          variants (ptp_active=0, ptp_active=1 with/without metrics).

Approach: Call a thin wrapper around the fprintf/fwrite logic extracted into
          a helper function, or write the CSV to a tmpfile and parse it.
          Avoid depending on a live PtpClock; use a mock struct with known values.

Test cases:
  T1: ptp_active=0 — row has same column count as header.
  T2: ptp_active=1, have_metrics=0 — row has same column count as header.
  T3: ptp_active=1, have_metrics=1 — row has same column count as header.
  T4: All three variants written sequentially — csv.DictReader parses all rows
      without column-count errors (use a Python subprocess or a C CSV parser).
  T5: Column names match between #ifdef PTPD_STATISTICS=ON and OFF builds —
      row field count matches header field count in both configurations.

Sanitizers: UBSAN (format string), ASAN (tmpfile writes).

C3. test_monotonic_sleep.cpp
------------------------------------------------------------
Purpose : Verify the CLOCK_MONOTONIC deadline loop wakes within ±10 ms of
          target interval and that g_stop=1 causes early exit within 55 ms.

Approach: Extract the sleep block into a linkable helper:
  void monotonic_sleep_1s(volatile int *stop);
  -- Calls clock_gettime(CLOCK_MONOTONIC) for deadline.
  -- Loops 50 ms nanosleep slices until deadline or *stop != 0.

Test cases:
  T1: Normal 1 s sleep — measured wall time in [950 ms, 1100 ms].
  T2: *stop set to 1 after 200 ms from a second thread — function returns
      within 250 ms of the stop signal (200 ms delay + 50 ms worst slice).
  T3: Called immediately after a simulated CLOCK_REALTIME backward step
      (advance CLOCK_MONOTONIC by manipulating test fixture) — deadline
      is correctly computed relative to CLOCK_MONOTONIC, not CLOCK_REALTIME.
  T4: Repeated calls 600 times (simulate full 10-min run) — total elapsed
      CLOCK_MONOTONIC time in [598 s, 602 s] (1 s per iteration ± 0.1%).

Notes: T3 cannot directly step CLOCK_REALTIME in a test binary (requires root).
       Use a mock clock abstraction injected via function pointer or parameter
       to simulate the step.

Sanitizers: TSAN (stop flag written from two threads in T2).

C4. test_network.cpp
------------------------------------------------------------
Purpose : Verify the PTP grandmaster at 192.168.8.234 is reachable and that
          the en5 interface is up BEFORE running servo comparison tests.
          Marks tests as SKIPPED (not FAILED) when hardware is absent.

Approach: Use POSIX sockets — no external tools.

Test cases:
  T1: en5 interface exists and has an IPv4 address.
        getifaddrs() → iterate → find en5 with AF_INET.
        GTEST_SKIP() if not present.
  T2: 192.168.8.234 responds to ICMP echo (ping via raw socket or SOCK_DGRAM
      IPPROTO_ICMP — works without root on macOS).
        GTEST_SKIP() if unreachable.
  T3: UDP port 319 (PTP event) is bindable on en5.
        socket(AF_INET, SOCK_DGRAM, 0) → bind() → close().
        FAIL if EADDRINUSE (stray ptpd-app still running).
  T4: UDP port 320 (PTP general) is bindable on en5.
  T5: No ptpd-app process is currently running (check /proc or pgrep on macOS).

These tests should be run as a pre-flight check before compare-servo-options.sh.
They are also the only tests that genuinely require the test machine to be
connected to the PTP network; all other tests should pass without it.

Sanitizers: N/A (socket I/O; sanitizers not useful here).

------------------------------------------------------------
C5. test_swclock_rwlock.cpp
------------------------------------------------------------
Purpose : Regression test for the rdlock starvation scenario.
          Verify that a reader thread calling swclock_get_remaining_phase_ns()
          or swclock_get_metrics() is NOT starved when a high-frequency writer
          thread is also running (simulating the 100 Hz poll thread).

Approach: Use swclock's public API directly (no ptpd required).

Setup:
  1. swclock_create() → configure with nominal parameters.
  2. Launch a "poll thread" that calls swclock_adjtime() 100×/s for N seconds.
     This acquires wrlock at 100 Hz — same as the real poll thread.
  3. Launch a "monitor thread" that calls swclock_get_remaining_phase_ns()
     and swclock_get_metrics() at 1 Hz and records the call latency.

Test cases:
  T1: Reader latency — All swclock_get_remaining_phase_ns() calls return
      within 100 ms while the poll thread is active.
      (100 ms budget: 10× one poll cycle of 10 ms).
  T2: Reader never starves — Over 30 s test, the monitor thread completes
      at least 28 successful reads (≥93% completion rate).
  T3: No data races — Test passes cleanly under TSAN.
  T4: After poll thread exits, reader continues normally.

Notes: This test was the root cause of ptp_active rows stopping at ~34.
       If this test fails under TSAN, it directly identifies the race condition
       that causes the production hang.

Sanitizers: TSAN (primary value — detects the rwlock race).
            ASAN (detect any memory errors in swclock under concurrent load).

NOTE: The swclock submodule already has src-gtests/tests_sw_clock.cpp with

New tests to add in the ptpd src-gtests (not the submodule):

  T1: swclock_create() + swclock_get_metrics() before any adjtime call

  T2: swclock_get_remaining_phase_ns() with zero phase — returns 0.

D. SANITIZER STRATEGY
================================================================================

The existing build tree already has ASAN, TSAN, UBSAN build directories:
  build-cmake/asan/
  build-cmake/tsan/
  build-cmake/ubsan/

These were configured for the main ptpd binary but do NOT currently include
BUILD_PTPD_TESTS=ON or BUILD_PTPD_LIBRARY=ON (ptpd-app is not built there).

Proposed changes to sanitizer build scripts (scripts/build/):

  D1. config-cmake-asan.sh — add:
        -DBUILD_PTPD_TESTS=ON \
        -DBUILD_PTPD_LIBRARY=ON

  D2. config-cmake-tsan.sh — add same.

  D3. config-cmake-ubsan.sh — add same.

  D4. New script: scripts/testing/run-ptpd-tests.sh
      Usage: bash scripts/testing/run-ptpd-tests.sh [asan|tsan|ubsan|debug]

      Actions:
        1. Re-configure the requested sanitizer build with tests enabled.
        2. cmake --build build-cmake/<sanitizer> --target ptpd_gtests
        3. cd build-cmake/<sanitizer> && ctest -V --output-on-failure
        4. For ASAN/UBSAN: set ASAN_OPTIONS=halt_on_error=1:detect_leaks=1
        5. For TSAN: set TSAN_OPTIONS=halt_on_error=1

      Exit code: CTest exit code (0 = all pass).

Sanitizer target matrix:

  Test file                  ASAN   TSAN   UBSAN   Notes
  -------------------------  -----  -----  ------  ---------------------------
  test_strip_arg.cpp          YES    no     YES    Pure logic, no threads
  test_monitor_csv.cpp        YES    no     YES    File I/O + format strings
  test_monotonic_sleep.cpp    YES    YES    no     Two-thread stop signal test
  test_network.cpp            no     no     no     Socket I/O; sanitizers N/A
  test_swclock_rwlock.cpp     YES    YES    no     Concurrency — TSAN is key
  test_swclock_integration.cpp YES   no     YES    Library API calls

  Note: TSAN and ASAN cannot be combined in a single binary (incompatible
  sanitizers). Run them separately.

  macOS-specific: LeakSanitizer is not available on macOS (only Linux).
  Use ASAN_OPTIONS=detect_leaks=0 on macOS to avoid false ASAN abort.

E. CMAKE INTEGRATION
================================================================================

  E1. src-gtests/CMakeLists.txt (new file)
  ----------------------------------------

  cmake_minimum_required(VERSION 3.16)

  # Option guard — only build tests if explicitly enabled
  if(NOT BUILD_PTPD_TESTS)
      return()
  endif()

  find_package(GTest REQUIRED)

  # Helper header shared across all test files
  # Contains: MockPtpClock struct, temp file utilities, etc.
  set(TEST_HELPER_HEADERS ${CMAKE_CURRENT_SOURCE_DIR}/test_helpers.h)

  # Function to define one test target with consistent flags and links
  function(ptpd_test target sources)
      add_executable(${target} ${sources} ${TEST_HELPER_HEADERS})
      target_link_libraries(${target} PRIVATE GTest::gtest_main ptpd-shared)
      if(BUILD_WITH_SWCLOCK)
          target_link_libraries(${target} PRIVATE swclock)
          target_include_directories(${target} PRIVATE
              ${CMAKE_SOURCE_DIR}/libraries/swclock/src/sw_clock)
          target_compile_definitions(${target} PRIVATE PTPD_USE_SWCLOCK)
      endif()
      target_include_directories(${target} PRIVATE
          ${PROJECT_BINARY_DIR}       # config.h
          ${CMAKE_SOURCE_DIR}/src     # ptpd headers
          ${CMAKE_SOURCE_DIR}/src-app/macos)
      target_compile_definitions(${target} PRIVATE HAVE_CONFIG_H)
      add_test(NAME ${target} COMMAND ${target})
  endfunction()

  ptpd_test(test_strip_arg         test_strip_arg.cpp)
  ptpd_test(test_monitor_csv       test_monitor_csv.cpp)
  ptpd_test(test_monotonic_sleep   test_monotonic_sleep.cpp)
  ptpd_test(test_network           test_network.cpp)
  ptpd_test(test_swclock_rwlock    test_swclock_rwlock.cpp)
  ptpd_test(test_swclock_integration test_swclock_integration.cpp)

  E2. Top-level CMakeLists.txt additions
  ---------------------------------------
  After the existing add_subdirectory(src-app) block, add:

  option(BUILD_PTPD_TESTS "Build GoogleTest unit/integration tests" OFF)
  if(BUILD_PTPD_TESTS)
      if(NOT TARGET ptpd-shared)
          message(FATAL_ERROR
              "BUILD_PTPD_TESTS requires BUILD_PTPD_LIBRARY=ON")
      endif()

  E3. Dependency on strip_arg() and monitor logic
  ------------------------------------------------
  strip_arg() and the CLOCK_MONOTONIC sleep block are currently defined
  as file-static functions in ptpd-app.c with no external linkage.
  Two options:

  Option A (minimal refactor — preferred):
    Add a compile-time escape hatch:
      #ifndef PTPD_APP_TESTING
      static int strip_arg(...) { ... }
      static void monotonic_sleep_1s(...) { ... }
      #else
      int strip_arg(...) { ... }         // non-static for test linkage
      void monotonic_sleep_1s(...) { ... }
      #endif
    Test target adds -DPTPD_APP_TESTING to compiler flags and links
    ptpd-app.c directly (without main()).

  Option B (cleaner but requires source change):
    Extract strip_arg() and the sleep helper into
    src-app/macos/ptpd_app_utils.c + ptpd_app_utils.h.
    ptpd-app.c includes them. Tests link ptpd_app_utils.c directly.

  Recommendation: Option B — cleaner dependency graph, no macro hacks.
  Requires approval before modifying ptpd-app.c.
