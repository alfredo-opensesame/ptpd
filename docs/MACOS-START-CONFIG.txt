================================================================================
 HOW THE macOS ptpd-app IS CONFIGURED AND STARTED — COMPLETE WALKTHROUGH
================================================================================

This document traces every step from the shell invocation through binary startup,
argument parsing, configuration loading, and protocol thread launch.

--------------------------------------------------------------------------------
SECTION 1 — INVOCATION
--------------------------------------------------------------------------------

The entry point is the bash script:

    scripts/testing/ptp-app-run.sh  <interface>  <config_file>  [options]

Example:

    sudo scripts/testing/ptp-app-run.sh en5 resources/ptpd-daemon.conf \
         -b ptpd-app -d 120

Command-line arguments accepted by the script
----------------------------------------------
  Argument 1 (positional)  : Network interface.  Required.  e.g. "en5".
  Argument 2 (positional)  : Path to a config file.  Required.
  -b / --binary  NAME      : Binary to use.
                               "ptpd2"    → build-cmake/debug/src/ptpd2
                               "ptpd-app" → build-cmake/debug/src-app/ptpd-app
                             Default: ptpd2
  -d / --duration N        : How many seconds to run before stopping.
                             Default: 60 s
  -v / --verbose           : Enable verbose shell output.

The script resolves the binary path by searching build-cmake/debug then
build-cmake/release. If neither contains the binary the script exits with an
error.


--------------------------------------------------------------------------------
SECTION 2 — PRE-LAUNCH CLEANUP
--------------------------------------------------------------------------------

Before starting the daemon the script ensures no competing ptpd process is
running.  The function stop_ptpd_processes() carries out a multi-step kill:

Step 0: brew services stop <any service with "ptpd" in its name>
Step 1: launchctl bootout  (system domain and gui/$UID) for every launchd job
        whose label matches /ptpd(_app)?(2)?/
Step 2: launchctl bootout  by on-disk plist path for
        /Library/LaunchDaemons/*ptpd*.plist  (and LaunchAgents equivalents)
Step 3: sudo pkill -TERM / -KILL for any process matching
        the regex  (^|/)(ptpd2?|ptpd[-_][Aa]pp)([[:space:]]|$)
Step 4: Remove lock / pid files from:
          /var/run, /private/var/run, /tmp,
          /usr/local/var/run, /opt/homebrew/var/run
Step 5: sudo lsof -ti :319 -ti :320 — force-kill anything still holding PTP
        ports 319 or 320


--------------------------------------------------------------------------------
SECTION 3 — OUTPUT DIRECTORY AND PACKET CAPTURE SETUP
--------------------------------------------------------------------------------

setup_output() creates a timestamped directory under scripts/ptpd_logs/, e.g.
    scripts/ptpd_logs/20260312_220035/

Inside it:
    ptpd_daemon_en5.log   – daemon log (stdout+stderr redirected here)
    ptpd_daemon_en5.csv   – ptpd statistics CSV (written by ptpd itself)
    ptp_en5.pcap          – tcpdump packet capture

Packet capture is started immediately:
    sudo tcpdump -i en5 -n -U \
        '(udp port 319 or 320 or 10319 or 10320)' \
        -w ptp_en5.pcap


--------------------------------------------------------------------------------
SECTION 4 — CONFIGURATION FILE PREPARATION (setup_configuration)
--------------------------------------------------------------------------------

4.1 Path resolution
-------------------
The script resolves the config file path in this priority order:
  1. Absolute path (starts with /)
  2. $PWD/<path>
  3. $PROJECT_DIR/<path>  (repository root)
  4. $SCRIPT_DIR/<path>

If none match, the script aborts.

4.2 Pre-flight validation
--------------------------
The script calls:
    sudo ptpd2 -c <resolved_conf> -k

The -k flag tells ptpd to parse the config file, check all settings for
validity, print any errors, and exit without starting the daemon.  This is
implemented in loadCommandLineOptions() → case 'k': rtOpts->checkConfigOnly.
If ptpd exits non-zero the script aborts.

4.3 Config file copy + runtime appended overrides
---------------------------------------------------
The resolved config file is COPIED to:
    $OUTPUT_DIR/ptpd-daemon.conf

Then these lines are APPENDED to the copy:

    ; Runtime overrides for test run (daemon mode)
    ptpengine:interface = en5
    global:log_file     = $OUTPUT_DIR/ptpd_daemon_en5.log
    global:statistics_file = $OUTPUT_DIR/ptpd_daemon_en5.csv
    global:statistics_update_interval = 1
    global:lock_directory = $OUTPUT_DIR/locks

Because the config file is read AFTER command-line args are merged into the
candidate dictionary (but CLI args win on conflict — see Section 7), the
interface appended here will be effective unless -i is also passed on the
command line.

4.4 Base config file (resources/ptpd-daemon.conf)
---------------------------------------------------
The checked-in template contains:

    ptpengine:interface                = en5
    ptpengine:domain                   = 0
    ptpengine:preset                   = slaveonly
    ptpengine:ip_mode                  = unicast
    ptpengine:unicast_destinations     = 192.168.68.114
    ptpengine:unicast_negotiation      = y
    ptpengine:transport                = ipv4
    ptpengine:always_respect_utc_offset= y
    ptpengine:delay_mechanism          = E2E
    ptpengine:announce_receipt_timeout = 3
    ptpengine:log_announce_interval    = 1
    ptpengine:log_sync_interval        = 0
    ptpengine:log_delayreq_interval    = 0

    global:log_file                    = /tmp/ptpd_daemon.log
    global:log_level                   = LOG_ALL
    global:use_syslog                  = n
    global:verbose_foreground          = n
    global:statistics_file             = /tmp/ptpd_daemon.csv
    global:log_statistics              = y

    clock:no_adjust                    = N
    clock:drift_handling               = reset
    clock:step_startup                 = y
    clock:step_startup_force           = y

    servo:kp                           = 0.01
    servo:ki                           = 0.0001

The runtime-appended block overrides interface, log_file, statistics_file,
and lock_directory.


--------------------------------------------------------------------------------
SECTION 5 — BINARY ARGUMENT CONSTRUCTION (setup_binary_args)
--------------------------------------------------------------------------------

The script builds the argv array that will be passed to the binary:

    BINARY_ARGS=(
        -C               # global:foreground=Y (don't daemonize — run in foreground)
        -c "$CONFIG_FILE" # full path to the prepared config file copy
        -i "$INTERFACE"   # ptpengine:interface override on command line
        -D -D -D         # increment debug level 3 times (LOG_DEBUG3)
    )

Final command executed (run_binary):

    sudo /bin/bash -c \
      "\"$BINARY\" -C -c \"$CONFIG_FILE\" -i en5 -D -D -D \
       >> \"$LOG_FILE\" 2>&1 &"

Both stdout and stderr are redirected to LOG_FILE.  The & means it runs in
the background; the shell stores the child PID in BINARY_PID for later kill.


--------------------------------------------------------------------------------
SECTION 6 — ptpd-app BINARY ENTRY POINT (src-app/macos/ptpd-app.c:main)
--------------------------------------------------------------------------------

ptpd-app has its own custom flags that ptpd's core does not understand.
Before forwarding argc/argv to ptpd_init(), main() strips them:

    --show-time           sets show_time=1; removed from argv
    --servo-log  <path>   saves path to servo_log_path; removed from argv
    --swclock-log <path>  saves path to swclock_log_path; removed from argv
    --pidfile    <path>   saves path to pidfile_path; removed from argv

strip_arg() (in ptpd_app_utils.c) removes the flag and its optional argument
by shifting the remaining elements down and decrementing argc in-place.

After stripping, the effective argv seen by ptpd_init() is:
    ["ptpd-app", "-C", "-c", "<conf>", "-i", "en5", "-D", "-D", "-D"]

Signal handlers for SIGINT and SIGTERM are registered (set g_stop = 1).

CLOCK_REALTIME and CLOCK_MONOTONIC start timestamps are saved (used later
by the monitor thread for elapsed_s column).

If --pidfile was given, the PID is written to that file before init so the
calling script can send SIGTERM to exactly this process.


--------------------------------------------------------------------------------
SECTION 7 — ptpd_init() AND ptpdStartup() — CORE INIT SEQUENCE
--------------------------------------------------------------------------------

ptpd_init() (src/ptpd.c)
-------------------------
Calls ptpd_common_init(argc, argv, ret), which calls ptpdStartup().
If successful, stores the returned PtpClock* in library_ptpClock.

After ptpdStartup() returns:
  - If PTPD_USE_SWCLOCK: allocates and attaches a SwClock instance.
  - Configures the TimingDomain (priority, type, timeout, update interval).
  - Calls timingDomain.init(&timingDomain).

ptpdStartup() (src/dep/startup.c)
----------------------------------
This is the heavy-lifting initialization.  Full step-by-step:

STEP A — Load default settings
    loadDefaultSettings(rtOpts)
    Fills all rtOpts fields with compiled-in defaults (servo gains, timeouts,
    file paths, feature flags, etc.)

STEP B — Allocate dictionaries
    rtOpts->candidateConfig = dictionary_new(0)
    rtOpts->cliConfig       = dictionary_new(0)
    Two iniparser dictionaries are used:
      candidateConfig — merged result of config file + CLI
      cliConfig       — command-line settings only

STEP C — loadCommandLineKeys(cliConfig, argc, argv)
    Scans argv for --section:key=value or --section:key value arguments.
    These are stored directly in cliConfig AND their argv[] slots are cleared
    to empty strings "" so getopt won't see them.

STEP D — loadCommandLineOptions(rtOpts, cliConfig, argc, argv, ret)
    Runs getopt_long() over the (cleaned) argv.
    The option string is:
        "?c:kb:i:d:sgmGMWyUu:nf:S:r:DvCVHTt:he:Y:tOLEPAaR:l:p"
    Relevant cases for our argv:
      -C  → rtOpts->nonDaemon=1; dict set global:foreground=Y
      -c  → strncpy(rtOpts->configFile, optarg, PATH_MAX)
      -i  → dict set ptpengine:interface = "en5"
      -D  → rtOpts->debug_level++ (called 3 times → debug_level=3 = LOG_DEBUG3)

    After parsing, rtOpts->configFile contains the full path to the prepared
    config file copy.

STEP E — Print startup banner
    NOTIFY("%s version %s starting\n", USER_DESCRIPTION, USER_VERSION)
    dump_command_line_parameters(argc, argv)   (logs all argv[i] to INFO)

STEP F — Load config file (if rtOpts->configFile is non-empty)
    INFO("Loading configuration file: %s\n", rtOpts->configFile)
    loadConfigFile(&rtOpts->candidateConfig, rtOpts)
      → iniparser_load(rtOpts->configFile) — parses the INI file into a dict
      → loops over all substitution variables:
           "replacing @pid@ with <PID> in config"      (variables:pid)
           "replacing @hostname@ with <host> in config" (variables:hostname)
      Merges the loaded file dict into candidateConfig.
    Then: dictionary_merge(cliConfig, candidateConfig, 1, 1, "from command line")
    CLI values WIN over config file values because cliConfig is merged LAST
    with overwrite=1.

STEP G — parseConfig(CFGOP_PARSE, NULL, candidateConfig, rtOpts)
    The "config compiler".  Iterates every known section:key.
    For each known key:
      - Reads the value from candidateConfig (or uses the default)
      - Validates type, range, dependencies
      - Writes the final value into rtOpts fields AND into rtOpts->currentConfig
    Returns NULL on any error (missing required key, out-of-range value,
    conflicting options).

    CONFIG_KEY_REQUIRED("ptpengine:interface") is checked here.
    Because -i en5 was passed on the CLI (stored in cliConfig, which was merged
    with overwrite into candidateConfig), this key is present and valid.
    The interface name is stored in rtOpts->primaryIfaceName.

STEP H — Network interface test
    testInterface(rtOpts->primaryIfaceName, rtOpts)
    Opens a test socket on the interface to confirm it exists and is usable.
    Aborts if the interface cannot be opened.

STEP I — Lock file
    Unless global:ignore_lock=Y (-L), ptpd creates a lock file in
    global:lock_directory (set to $OUTPUT_DIR/locks by the appended config
    override) to prevent two daemons running on the same interface.

STEP J — Shared memory, NTP setup (if enabled), logging init
    Opens a POSIX shared memory segment for statistics (IPC with external
    monitoring tools).  Initialises the stats file descriptor for CSV output.
    Because global:log_statistics=y is set, the CSV is opened for writing.

STEP K — Return PtpClock*
    ptpdStartup() allocates and zero-fills the PtpClock structure, sets
    portDS, defaultDS, currentDS, parentDS, timePropertiesDS from rtOpts,
    and returns the pointer.


--------------------------------------------------------------------------------
SECTION 8 — ptpd_start() — PROTOCOL THREAD LAUNCH
--------------------------------------------------------------------------------

ptpd_start(ptpClock) (src/ptpd.c):
  Sets thread_running = TRUE.
  Calls pthread_create(&protocol_thread, NULL, ptpd_protocol_thread, ptpClock).

ptpd_protocol_thread:
  Sets G_ptpClock = ptpClock  (global used by logging).
  Calls protocol(&rtOpts, ptpClock)  — the main IEEE 1588 state machine loop.
    This runs in a tight select()/recvmsg() loop, handling:
      - PTP_INITIALIZING → PTP_LISTENING
      - Grant negotiation for unicast mode (REQUEST_UNICAST_TRANSMISSION)
      - PTP_LISTENING → PTP_SLAVE after receiving Announce grants
      - Sync + Follow_Up processing, delay request/response, servo updates

Back in ptpd-app main():
  After ptpd_start() returns, main() re-installs its own SIGINT/SIGTERM
  handlers (ptpd_init → ptpdStartup → catchSignals overwrites them;
  re-registering here is intentional).

If --servo-log was given:
  fopen(servo_log_path, "w"); pthread_create(&g_monitor_tid, monitor_thread, fp)
  The monitor thread wakes every 1 s, reads servo internals and swclock
  metrics from the shared PtpClock structure, and writes a CSV row.

If --swclock-log was given:
  swclock_start_log((SwClock*)g_ptp->swclock, swclock_log_path)

Main loop:
  while (!g_stop) sleep(1);

  g_stop is set to 1 by the SIGTERM/SIGINT handler.
  The script sends SIGTERM after $DURATION seconds (or SIGINT on Ctrl+C).

Cleanup:
  pthread_join(g_monitor_tid)  (waits for monitor thread)
  ptpd_shutdown(ptpClock)      → sets ptpClock->library_should_exit=TRUE
                                  joins protocol_thread
                                  calls ptpd_common_cleanup()
                                    → swclock_destroy()
                                    → timingDomain.shutdown()
                                       → ptpServiceShutdown()
                                           → ptpdShutdown()
                                               → network close, dict free, etc.
  unlink(pidfile_path)


--------------------------------------------------------------------------------
SECTION 9 — POST-RUN ANALYSIS
--------------------------------------------------------------------------------

After the daemon exits, the script calls analyze_results():

  - Stops tcpdump (SIGTERM on TCPDUMP_PID)
  - tcpdump -nn -r ptp_en5.pcap 'udp port 319' — counts event port packets
  - tcpdump -nn -r ptp_en5.pcap 'udp port 320' — counts general port packets
  - Parses ptpd_daemon_en5.csv for rows with state="slv" to find the final
    offset value and assess sync quality:
      < 1 ms    → Excellent
      < 10 ms   → Good
      < 100 ms  → Acceptable
      ≥ 100 ms  → Poor
  - Runs scripts/analysis/analyze_ptp.py (if present)
  - Runs scripts/analysis/analyze_pcap.sh (if present)

SECTION 11 — CONFIG PRIORITY ORDER (highest to lowest)
--------------------------------------------------------------------------------

  1. Command-line -i <interface>  (stored in cliConfig, merged with overwrite)
  2. Appended runtime overrides in the config file copy
     (ptpengine:interface, global:log_file, global:statistics_file, etc.)
  3. Settings in the original config file (resources/ptpd-daemon.conf)
  4. Compiled-in defaults from loadDefaultSettings()

Because dictionary_merge(cliConfig, candidateConfig, overwrite=1) is called
AFTER the config file is loaded into candidateConfig, CLI values win over all
config file values.

The runtime-appended lines are part of the same config file (appended before
iniparser_load), so they share priority #2/#3 position with the original
settings.  Within the same file, the LAST occurrence of a duplicate key wins
in iniparser, which means the appended lines override the earlier ones for
ptpengine:interface, global:log_file, and global:statistics_file.
