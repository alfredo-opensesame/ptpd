iOS PTPd Library Fixes
======================

The following changes were made to get the ptpd library (libptpd2.a) running
correctly inside the iOS PTPMonitor app (simulator and device).


1. PTPD_LIBRARY_MODE — select() blocking forever
-------------------------------------------------
Problem:
  In src/dep/net.c, netSelect() calls select() with a NULL timeout when
  PTPD_LIBRARY_MODE is not defined. On iOS the protocol engine runs in a
  background pthread (not the main thread), so a blocking select() with no
  timeout means timer ticks never fire: UNICAST_GRANT timer never expires,
  no REQUEST_UNICAST_TRANSMISSION is ever sent, the master never grants
  anything.

Fix:
  The flag -DPTPD_LIBRARY_MODE=1 was added to OTHER_CFLAGS in the Xcode
  project at build-cmake/ios-simulator/ptpd.xcodeproj.
  With this flag, netSelect() uses a 31.25 ms fallback timeout so the
  polling loop wakes up regularly and timer ticks are processed.

  The flag was already present in the Xcode project but the library
  (libptpd2.a) was stale (built Feb 19 before the flag was added).
  The fix was to rebuild the ptpd2 target:
    xcodebuild -project build-cmake/ios-simulator/ptpd.xcodeproj \
               -target ptpd2 -sdk iphonesimulator build


2. Always-rebuild dependency chain in CMakeLists.txt
----------------------------------------------------
Problem:
  src-app/ios/CMakeLists.txt used STATIC IMPORTED library stubs for
  libptpd2.a and libswclock.a. CMake never knew to rebuild them when
  source files changed, so the app could link against a stale library.

Fix:
  Replaced the IMPORTED stubs with add_custom_target(ALL) entries that
  invoke xcodebuild on the ios-simulator Xcode project before the app
  links. xcodebuild is incremental so it is fast when nothing changed.

  Relevant additions in src-app/ios/CMakeLists.txt:
    add_custom_target(build_ptpdios ALL
        COMMAND xcodebuild -project .../ios-simulator/ptpd.xcodeproj
                           -target ptpd2 -sdk iphonesimulator ...)
    add_custom_target(build_swclock_ios ALL
        COMMAND xcodebuild -project .../ios-simulator/ptpd.xcodeproj
                           -target swclock -sdk iphonesimulator ...)
    add_dependencies(PTPMonitor build_ptpdios build_swclock_ios)


3. Config parity — bundle the real ptpd-daemon.conf
----------------------------------------------------
Problem:
  PTPBridge.m was generating a hardcoded config string. It diverged from
  resources/ptpd-daemon.conf (missing global:log_statistics=y, different
  servo:kp/ki, etc.), making it impossible to compare iOS vs macOS behaviour.

Fix:
  resources/ptpd-daemon.conf is now bundled as an app resource.
  In src-app/ios/CMakeLists.txt:
    set_source_files_properties(
        .../resources/ptpd-daemon.conf
        PROPERTIES MACOSX_PACKAGE_LOCATION Resources)

  PTPBridge.m reads the file from the app bundle at runtime:
    NSString *bundleConfPath =
        [[NSBundle mainBundle] pathForResource:@"ptpd-daemon" ofType:@"conf"];

  Two lines are patched at runtime before writing to a temp file:
    ptpengine:interface   → set to the chosen interface (e.g. en5)
    ptpengine:unicast_destinations → set to the master IP

  Lines incompatible with iOS are stripped:
    global:log_file
    global:statistics_file

  The patched config is written to NSTemporaryDirectory()/ptpmonitor.conf
  and passed to ptpdlib_init() as -c <path>.


4. argc / argv — removed duplicate -i flag
------------------------------------------
Problem:
  The original argv passed both -c <conf> and -i <interface>. Since the
  interface is now set inside the config file by the patching step above,
  the -i flag is redundant and caused a conflict.

Fix:
  argv in PTPBridge.m is now:
    { "ptpd", "-C", "-c", cfgPathCStr, "-L", NULL }   (argc = 5)
  The -i flag is gone.


5. Autostart via launch arguments
----------------------------------
Added support for driving the app without UI interaction:
  -PTPAutoStart          start PTP immediately on launch
  -PTPMasterIP <ip>      set the unicast master destination
  -PTPInterface <iface>  select the network interface

Implemented in PTPManager.swift checkAutoStart(), called from
ContentView.onAppear.

Example:
  xcrun simctl launch <udid> com.example.ptpmonitor \
      --args -PTPAutoStart -PTPMasterIP 192.168.68.114 -PTPInterface en5


6. Default interface — prefer en5
----------------------------------
ContentView.swift now selects en5 as the default interface in the picker
if it is available, falling back to the first available interface:
  selectedInterface =
      ptpManager.availableInterfaces.first(where: { $0.name == "en5" })?.name
      ?? ptpManager.availableInterfaces.first?.name ?? ""
